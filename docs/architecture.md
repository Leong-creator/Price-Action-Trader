# 当前架构

## 盘中主系统

M15 是唯一盘中交易系统：

`官方长桥SDK单一AsyncQuoteContext -> 回调有界队列 -> 顺序五分钟聚合 -> 冻结策略合同 -> 快速风控 -> 长桥模拟账户SDK订单`

- 行情连接：一个独立子进程持有唯一官方 SDK `AsyncQuoteContext` 和一个事件循环，同时接收147只标的的报价和逐笔成交推送。同步桥接调用等待Future，不能再用保留GIL的同步SDK请求阻塞回调；不存在第二个同步行情上下文。
- 行情初始化：同一连接读取60根日线和一次初始快照；二者没有订单资格。盘后16:10起同一连接逐标的更新日线，完整后一次发布，失败停止，不在盘中补拉。
- 回调：只校验时间戳、规范化数据和入队，不执行策略、账户请求、文件统计或订单请求。
- 顺序处理器：消费队列、按官方美股成交类型分别计算价格和成交量；边界后保留2秒到达窗口，必须在5秒内完成。未处理回调清空前不封口，迟到到已封口K线的成交停止并留证。
- 交易连接：账户、订单和退出使用独立官方 SDK 上下文。

## 数据资格

- 可开仓：仅盘中按时形成、边界完整、来源为 `official_sdk_push` 或 `official_sdk_trade_push` 的实时K线。
- 仅退出：行情不明、账户不明、配置漂移、部署清单失效或完整交易日门禁未通过。
- 不可开仓：初始快照、历史K线、盘后补录、无成交延续K线、人工诊断和本地模拟数据。

## 故障模型

- 行情状态只有连接中、已订阅、正常推送和 `fault_halted`。
- 连接建立上限30秒，订阅和日线初始化使用各自配置时限，K线边界完成上限5秒。
- 任一关键故障直接进入 `fault_halted`，关闭新开仓并保留诊断证据。
- 项目代码不自动重试、不重建行情上下文、不切换端点、不回退CLI或快照。官方4.5.0内部存在不可由Python关闭的重连，且没有断线回调；因此单个上下文或子进程不等于零重连。此限制尚未解决，见[SDK生命周期核对](decisions/20260907-sdk-lifecycle-verification.md)。
- 看护器只观察进程、配置、行情、账户和门禁状态，不负责行情自愈。
- 会话证据按纽约交易日和唯一K线边界隔离；重复/旧心跳不续命，空闲路径也检查边界5秒截止。全部已验证边界先审计落盘，再筛选可执行新鲜行情；写盘失败或可交易行过期都不得签发完整日通过。

## 部署治理

- `main` 是唯一稳定基线，禁止直接开发。
- 每个改动从最新 `main` 建独立 `codex/*` 分支，形成可运行检查点后推送，验收后再合并。
- 新开仓要求工作区干净、提交已存在远端、部署清单与配置及运行源码一致。
- 交易时段禁止编辑生产源码；紧急故障先停止新开仓并保存证据。

## 本地研究系统

本地研究与修复系统只做盘后研究、未进入长桥的策略观察和参考统计。它与 M15 的行情、信号、订单、持仓和盈亏完全隔离，不是长桥下单上游。

## 扩展边界

生产池当前固定147只。连续三个完整交易日稳定后，300只扩展只能在独立分支先只读运行一个完整交易日，不能直接替换147只生产池。

历史架构与失效方案只保存在 `docs/archive/` 和 `docs/decisions/`。
