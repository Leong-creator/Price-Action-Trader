## 盘中主系统

M15 是唯一盘中交易系统：

`官方长桥SDK单一同步QuoteContext（候选） -> 回调有界队列 -> 顺序五分钟聚合 -> 冻结策略合同 -> 快速风控 -> 长桥模拟账户SDK订单`

- 候选行情连接：一个独立子进程持有唯一官方同步 `QuoteContext`，行情Config使用官方默认，整个当前行情集合一次提交Quote/Trade订阅（最多500只，生产池147不变）；旧分批配置及循环删除，500仅为输入上限而非实测容量。旧 `AsyncQuoteBridge` 不再进入候选路径。同步请求可能阻塞，因此父进程负责阶段期限与终止、确认子进程实际退出，不能只取消Future便宣称连接释放。候选仍需交易时段持续接收验证，周末不能排除回调阻塞风险。
- 行情初始化：同一连接读取60根日线和一次初始快照；二者没有订单资格。盘后16:10起同一连接逐标的更新日线，完整后一次发布，失败停止，不在盘中补拉。
- 回调：只校验时间戳、规范化数据和入队，不执行策略、账户请求、文件统计或订单请求。
- 顺序处理器：消费队列、按官方美股成交类型分别计算价格和成交量；边界后保留2秒到达窗口，必须在5秒内完成。未处理回调清空前不封口，迟到到已封口K线的成交停止并留证。
- 交易连接：账户、订单和退出的独立官方异步SDK上下文保持不变；仍供账户/历史读取使用的helper保留。行情使用默认Config不意味着整个项目没有手工端点。

## 数据资格

- 2026-09-08临时授权已到期。本轮只读诊断和行情验证不请求订单；一个完整交易日通过仅提供恢复资格依据，不自动恢复交易，也不复用旧授权。故障进程退出后不能声称仍在监控已有持仓。

- 可开仓：仅盘中按时形成、边界完整、来源为 `official_sdk_push` 或 `official_sdk_trade_push` 的实时K线。
- 仅退出：行情不明、账户不明、配置漂移、部署清单失效或完整交易日门禁未通过。
- 不可开仓：初始快照、历史K线、盘后补录、无成交延续K线、人工诊断和本地模拟数据。

## 故障模型

- 行情状态只有连接中、已订阅、正常推送和 `fault_halted`。
- 候选生产/pipeline父进程使用阶段绝对期限：初始化及订阅等阶段采用配置 `subscription_deadline_seconds`（当前45秒），日线上下文采用自身配置时限；相同阶段的进度不能反复延长期限。K线边界完成上限5秒。raw探针只有外部总时限监督，不套用生产阶段期限。
- 任一关键故障直接进入 `fault_halted`，关闭新开仓并保留诊断证据。
- 项目代码不自动重试、不重建行情上下文、不切换端点、不回退CLI或快照。官方4.5.0内部存在不可由Python关闭的重连，且没有断线回调；因此单个上下文或子进程不等于零重连。2026-09-19起以实际数据连续性、及时性、完整性验收，不要求证明零内部重连；不可观测事件仍记未知，发现断流或缺口立即停止。详见[SDK生命周期核对](decisions/20260907-sdk-lifecycle-verification.md)。
- 诊断按数据收到、进入处理、形成K线三阶段记录时间与数量；原始故障独立保存，正常态副本标记为故障前快照，缺字段显示未知而非伪造零值或健康。
- 看护器只观察进程、配置、行情、账户和门禁状态，不负责行情自愈。
- 会话证据按纽约交易日和唯一K线边界隔离；重复/旧心跳不续命，空闲路径也检查边界5秒截止。全部已验证边界先审计落盘，再筛选可执行新鲜行情；写盘失败或可交易行过期都不得签发完整日通过。

## 部署治理

- `main` 是唯一稳定基线，禁止直接开发。
- 每个改动从最新 `main` 建独立 `codex/*` 分支，形成可运行检查点后推送，验收后再合并。
- 正式环境须记录解释器、官方wheel及实际加载模块的校验值；来源不符不得正式启动。统一入口只有一个行情实例，测试和子进程使用同一已核验环境。
- 新开仓要求工作区干净、提交已存在远端、部署清单与配置及运行源码一致。
- 交易时段禁止编辑生产源码；紧急故障先停止新开仓并保存证据。
