# 当前执行规则

## 开始任务

1. 读取 `plans/active-plan.md`、`docs/status.md`、`docs/architecture.md`。
2. 获取最新 `origin/main`，从它创建单一主题的 `codex/*` 分支或独立工作树。
3. 修改前保存用户工作区；禁止丢弃来源不明的改动和运行产物。
4. 交易时段不修改生产源码。故障时先停止新开仓，保留已有持仓退出。

## M15 行情

- 生产配置只允许一个长期 `longbridge serve` JSON-RPC 行情连接；账户和订单继续固定使用持久 SDK 客户端。
- 固定147只策略池和池外已有持仓监控标的按每批10只订阅 `quote + trades`；必须核对订阅回执与初始报价完整覆盖，任一缺失都停止新开仓。
- 行情读取线程只解析整行 JSON 并写入有界队列；策略、账户、订单、文件和看板不得进入读取线程。
- `quote.trades` 生成K线，`quote.updated` 维护最新价格和健康。增量报价必须与初始快照按时间戳合并，旧快照不得覆盖新推送。五分钟边界后5秒内一次性封口完整147只批次。
- `no_trade_carry_forward`、快照、历史K线和盘后补录不得触发开仓。
- 行情二进制路径和校验值必须与生产配置一致；禁止自动回退快照轮询、禁止第二个行情连接、禁止 `longbridge serve` 调用交易写接口。

## M15 账户与订单

- 只允许 `lb_papertrading`，禁止实盘、真实资金、期权和融资。
- 账户快照每15秒后台刷新，超过45秒、账户类型不明或订单/持仓读取失败时停止新开仓。
- 账户刷新使用独立交易端点和独立工作进程；行情冷启动、退避和熔断期间不得暂停账户刷新，避免看护器因快照过旧替换行情父进程。
- 新开仓必须同时通过：部署清单、配置与源码指纹、实时行情边界、日线缓存、账户快照、策略合同和既有风控。
- 完整行情门禁固定为 `complete_session_gate_enabled=true`、`required_complete_sessions=1`。门禁只在一个常规交易时段的147只实时边界全部验收通过后记账；一小时连通性测试、盘后补录和旧版门禁文件都不能制造新的完整时段证据。
- 未取得长桥订单号只能记为待确认，不得重发；成绩只统计长桥实际成交。
- 本地模拟数据不得进入长桥信号、订单、持仓、退出或盈亏计算。

## 恢复

- 冷启动每批10只订阅最多等待30秒回执；订阅完成后的连接健康门槛仍为30秒，SPY和QQQ在常规交易时段同时静默超过30秒视为行情失活。
- 重连使用5、15、30、60秒退避，最多三次；失败后熔断新开仓，但保留同一主进程和账户/退出维护，冷却300秒后由同一进程重新订阅，禁止看护器按分钟重建全量订阅风暴。
- 每次重连前只清理由M15专属环境标记识别的遗留 `longbridge serve` 进程；不得清理人工或其他应用的长桥进程。
- 重连不补交断线期间信号，不重放历史买入或卖出草稿。
- 状态必须核验PID、命令行、进程启动标识、提交、配置、部署清单和更新时间。

## 部署

- 新开仓前运行本地治理检查并签发部署清单；清单只能针对干净且已推送远端的提交。
- 运行提交、配置或源码哈希与清单不一致时只允许退出。
- 每个主题依次执行：编译、聚焦单测、配置检查、敏感信息扫描、大文件检查、`git diff --check`。
- 分支推送后方可合并 `main`；每个稳定阶段创建标签。

## 验收

- 下一完整交易日只读要求：147/147订阅、8820条日线、78/78边界、11466/11466实时K线、零盘后补录、零行情重启、账户快照小于45秒、处理延迟95分位小于1秒。
- 一个完整交易时段通过后，下一交易日恢复模拟新开仓；连续三个完整交易时段通过后才宣布稳定。
- 300只扩展必须在稳定后从独立分支只读验收，不得修改147只稳定生产池。

历史执行规则已归档到 `docs/archive/2026-08-22/implement-before-marketdata-governance.md`，不得作为当前生产依据。
