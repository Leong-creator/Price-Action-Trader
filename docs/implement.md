# 主 Agent 执行手册

## 1. 执行主线

`plans/active-plan.md` 是当前唯一执行主线。

### 1.1 当前运行规则（覆盖后文历史阶段描述）

- 合同 v1 的正式启动、开盘验收和后台看护必须成套使用 `config/examples/m15_longbridge_sdk_runtime.contract_v1.json`、`config/examples/m15_opening_trade_readiness.paper_contract_v1.json`、`config/examples/m15_background_watchdog.contract_v1.json`。不得用旧 `m15_longbridge_sdk_runtime.json` 或 `paper_orders_enabled` 验收配置判断合同版进程，否则会产生虚假的配置指纹漂移。
- 合同 v1 正式测试标记进入 `active` 后必须规范化为 `blocks_new_entries=false`；全局标记只表达正式会话是否激活，具体资金池是否可新增由该仓实际持仓、待确认订单、成交归因和仓位上限独立决定。禁止用全局残留字段掩盖单仓超限，也禁止因一个超限仓冻结其他仓。
- 买入敞口必须在 SDK 请求发起后连续保留，直到满足以下任一条件：长桥确认零成交终态、精确成交归因确认持仓仍存在并接管相应数量、或精确成交归因确认该批次已平仓。订单尚未出现在账户快照、订单已成交但归因尚未刷新、部分成交后进入终态均不得提前释放敞口。
- 日线策略按“结构生命周期”生成实例编号。结构连续成立时，后续五分钟轮询只能更新确认信息并复用同一编号；只有当前活跃行情完成一次检测且明确返回结构不成立，才结束该生命周期。同一纽约交易日稍后重新形成的独立结构使用新编号，并重新接受持仓、挂单、敞口和全部策略风控。行情缺失、过期事件、未参与本轮检测或进程重启不得自动结束结构。五分钟策略继续按闭合K线实例区分。
- 历史虚拟持仓差额只能由 `run_m15_reconcile_broker_flat_virtual_lots.py` 依据模拟账户事实、真实长桥订单号和成交证据生成不计策略成绩的精确调整。账户仍有持仓时，只允许结清能证明属于旧测试编号且扣除后恰好等于券商实际数量的残量，禁止按标的或总数量猜测。
- 正式成绩必须同时满足测试编号匹配和开仓时间不早于该测试编号的 `test_started_at`。同编号的基线前验收成交只能进入审计归档；系统故障日继续保留长桥账户真实盈亏，但不得进入正常策略胜率、盈利因子和回撤判断。
- SDK 行情后备轮询必须一次覆盖完整交易池；中断轮询已经完成的K线必须先派发再切换轮询编号。行情覆盖数量不能替代五分钟K线连续性验收，缺口只允许阻断受影响的五分钟策略，不得伪造或回填交易信号。
- 当前合同 v1 生产配置直接使用正式测试编号，不配置 `validation_business_date` 或 `validation_end_at`，因此不得在纽约 `15:45` 执行全账户验收清仓。验收窗口能力只允许在人工明确批准的独立验收会话中成对配置；正式会话的退出仅由策略止损、目标、五分钟日内退出、日线最长持有和人工核准清仓触发。
- 正式基线激活前如需盘中验证，只允许在模拟账户持仓、挂单、待确认订单均为零且处于美股常规交易时段时，显式开启有截止时间的自然信号验证会话。验证必须使用独立于未来正式测试的验收编号，正式编号和正式开始时间不得在验收窗口内激活或写入验收订单。验证会话不得制造订单或放宽门槛；截止门禁必须在每批行情进入策略路由前执行，先关闭新开仓，再按长桥实际账户状态清理验证持仓，清理完成后等待正式激活时间并重置正式统计开始时间。
- 系统健康、策略候选、长桥真实提交是三个独立层级：行情和账户健康只能证明基础设施；路由候选证明策略检测工作；只有通过全部风控并取得长桥订单号才算真实提交，只有长桥 `Filled` 才算成交。被既定利润、收益风险比、整股、敞口或账户门禁阻断的自然候选不得称为漏单。
- 当前唯一长桥策略规则源是 `config/m15_strategy_contracts/*.json`。合同阶段固定为“规则草案、实时影子、模拟交易、完整执行版”；只有 `paper-v1` 或 `full-v1` 可以进入订单通道。运行进程、信号、执行流水、成交批次和看板必须携带相同合同哈希，缺失或漂移时只关闭对应信号，不允许回退旧简化规则。
- 合同 v1 只启用 8 条一仓一策略运行单元：`M10-PA-001-1d`、`M10-PA-002-5m`、`M10-PA-012-5m`、`M10-PA-004-MBF-QC-1d`、`M12-FTD-001-pullback-guard-confirm-1d` 以及 `M10-PA-002-5m-short`、`M10-PA-013-5m-short`、`M10-PA-011-ORB-R1-5m-short`。旧简化版、旧 PA002 修复版、旧 FTD 两版本和视觉原型不得混入新测试编号。
- `M10-PA-004-long-1d`、`M10-PA-007-1d`、`M10-PA-008-1d` 只能运行实时影子。它们必须完成 10 个正例、10 个反例、5 个边界例、强趋势/震荡/跳空/异常成交量样例、300 标的逐根回放、无未来数据检查、重启一致和至少一晚实时影子，才能单独晋级；不得合仓或提前下单。
- 三条视觉影子的证据必须分开记录为历史逐根回放、完整 SDK 交易日影子会话和人工图形样例复核。历史回放必须覆盖独立 `300` 只股票池并通过前缀无未来数据与重启一致性；完整会话必须由同一交易日每只 `78` 根常规时段五分钟 SDK K 线组成，缺任一标的、重复K线、非 SDK 来源或数据阻断都不得计日；机器自动筛选的样例候选不得直接增加人工通过计数。
- 视觉影子自动化复用现有盘后调度器，不新增 Windows 任务、常驻心跳或第二条行情连接。该步骤只读 M15 SDK 行情产物，不读取本地模拟账本，不创建信号、订单或账户操作；失败只能写入独立状态并保留三条影子策略的禁止下单状态，不得阻断 M15 现有八条执行合同。
- PA002 和 PA012 五分钟策略在纽约时间 15:55 强制市价退出。PA001、PA004-MBF-QC 和 FTD 日线合同最长持有 5 个美股交易日，在第 5 个交易日 15:55 市价退出；止损优先于期限退出，期限退出优先于普通目标限价。交易日历由冻结配置提供，不能读取本地模拟账本推断持有期。
- PA002/PA012 的 1 至 2 根跟进确认必须区分“第一根已确认”“第一根未确认但结构仍有效”和“第二根确认”三种状态，禁止用互斥条件让第二根确认永久不可达。两条五分钟合同只允许严格连续的五分钟K线；PA012 必须从纽约时间 09:35 第一根完整K线连续形成 30 分钟开盘区间，止损使用突破K线结构低点，目标仍使用开盘区间测量移动，之后继续接受统一 `1.5R` 与扣费后利润门禁。
- SDK 实时进程启动或重启如缺少当日五分钟上下文，任何时段都禁止再调用 SDK 历史接口追赶。实机已证明额外历史 `QuoteContext` 会与唯一实时行情连接竞争；系统必须先一次性建立完整 `300/300` 实时订阅，直接使用已有可信缓存，并只把存在时间缺口的五分钟运行单元标记为等待下一次干净会话。历史补齐属于独立盘后研究流程，不得进入 M15 实时进程。历史行始终只能作为 `context_only`，不得进入活跃事件、信号生成或订单重放；日线策略、账户快照和退出不受五分钟缺口影响。五分钟K线完成时必须冻结该边界内的当日 OHLCV，盘中日线确认不得使用边界后的最新报价改写历史K线。主进程开始恢复前必须先写实际 PID、配置指纹和启动状态；后台看护对同一正确 PID 的 `starting/starting_context_restore/connecting` 状态使用有界启动宽限，禁止每分钟误杀尚在正常恢复的进程。
- M15 自动路径只允许一个 SDK 行情上下文。实时连接必须在单次请求内订阅冻结的 `300` 只股票池；不得由慢统计、盘中历史恢复、验收脚本或额外异步客户端并行创建第二个行情上下文。订阅失败后必须先终止并回收旧进程，才能顺序启用唯一快照后备。后备轮询间隔 `3s`，每批 `100` 只、批间隔 `0.12s`，完整一轮必须覆盖 `300/300` 且不超过 `2.5s`；同一主进程少于三次重建时保持 `8s` 无进度切断，累计达到三次后仅在非五分钟边界使用最长 `60s` 恢复期限。已完成批次可更新主进程行情状态，但只有同一轮全部完成才允许形成策略K线批次；重建必须保留主进程K线状态和最初的半根K线抑制边界。SDK 子进程标准输出和错误输出必须静默，真实错误只通过结构化消息回传；主运行日志超过 `10MB` 时在下次启动前压缩归档。
- 8 条合同执行运行单元都必须按策略合同哈希隔离输出统一信号漏斗：检测尝试、未形成候选、候选、信号就绪和路由阻断原因。取得订单号、部分成交和完全成交继续只从长桥实际订单与成交对账合并，不得由路由器推测或用本地模拟补齐。
- 实时路由上下文必须按周期保留足够历史：每个日线运行单元至少保留 60 根日线，每个五分钟运行单元最多保留当日 78 根完整K线；不得再用统一 20 根尾部窗口让 PA001、PA012 等策略在检测前静默缺数据。
- 辅助模块不生成独立订单：PA015 的风险/数量约束为必选，PA014 目标价由每份策略合同拥有，PA006 只能由合同显式启用，PA003 只做本轮轻量排序，PA010 只维护视觉黄金样例，PA016 保持禁用。长桥运行时不得动态读取本地策略配置。
- 新基线切换必须使用 `scripts/run_m15_contract_v1_rollout.py --check` 完成只读预检。只有模拟账户、账户快照、合同目录和一仓一策略配置全部可信，才允许 `--prepare` 写入 `pending_flatten`；该命令本身不下单。实际持仓、挂单和待确认订单归零后只能由 SDK 状态机激活新测试，任何未知状态都必须保持停止新开仓。
- 合同切换清仓订单取得长桥订单号后必须按券商事实源跟踪终态。只有原订单被长桥明确标记为 `Canceled/Expired`、成交数量严格为零、模拟账户快照仍可信、当前没有活动挂单且同一实际持仓仍存在时，才允许用新的稳定请求编号重试一次；重试必须继续是仅退出的模拟账户市价单。部分成交、未知状态、缺少订单号、标的不匹配或重试自身失败时均禁止继续自动重发，保持停止新开仓并等待对账。
- 当清仓确认已经满足持仓、挂单和待确认订单全部为零，但 `activate_not_before` 尚未到达时，开盘验收和后台看护必须报告“清仓完成、等待激活”，不得误报故障，也不得提前打开新仓通道。

- PA002 双版本规则属于 2026-08-03 历史阶段。合同 v1 启用后只保留冻结的 `M10-PA-002-5m` 完整实时执行合同；`M10-PA-002-5m-repaired-v1` 归档且不得进入新基线。
- 修复版两连亏冷却只根据其长桥实际完整平仓批次计算，每累计两笔连续亏损只消耗一个后续合格信号；次日退出依据开仓纽约交易日生成，止损与止盈保留既有事件类型。未成交、取消、拒绝和待确认订单不得进入成绩或冷却判断。
- PA002 双版本里程碑随 M15 后台看护每 `300` 秒刷新，不新增 Windows 循环任务、终端弹窗或第二个交易进程。5日节点只给技术建议；最终节点要求两个版本各自达到15个有效交易日和100笔完整交易。系统只输出人工复核建议，禁止自动启用后续变体、自动切换版本或自动晋级。
- M15 五分钟热路径不得重复读取或重写完整信号与执行审计流水。正式运行进程只允许在启动时加载完整审计用于恢复去重集合和未终态订单，然后在内存中保留当前交易日阻断决策、所有已提交/待确认/失败订单及其对应信号；新增审计必须追加写入，完整历史继续作为慢路径事实证据。重启后的内存热状态必须与完整审计恢复结果等价，不能丢失重复提交保护、同日冷却、止损/止盈来源或做空回补身份。
- M15 盘中精确成交归因只在长桥订单状态、成交编号/数量/价格、实际持仓数量/可卖数量，或本地订单归因元数据发生变化时重建。单纯行情价格变化不得重复扫描全部历史成交。归因缓存签名必须包含测试编号、资金池、运行单元、策略、信号、止损和目标价；任一变化都必须失效重算，不能用缓存掩盖归因修正。
- 合同 v1 的 M15 唯一 SDK 连接、策略热上下文、路由、持仓管理和订单统一使用已验收的固定 300 只交易池；交易池成员和顺序由独立配置及指纹冻结。任何后续扩展标的必须先进入独立只读池完成覆盖、日线、延迟和稳定性验收，不得未经批准直接进入策略上下文或订单通道。
- M15 交易 SDK 必须每 60 秒执行一次无副作用的 TradeContext 只读健康检查。检测到 OAuth 刷新失败、交易上下文缺失或重建失败时，必须立即停止新开仓并在运行状态中显示具体恢复原因；不得把静态配置中的 `dispatch=true` 当成实际可交易，也不得重放失败前的旧信号。
- 做空开仓的券商容量只采用 `estimate_max_purchase_quantity(side=Sell)` 返回的 `cash_max_qty`。官方将 `Sell` 定义为美股卖空数量查询；`cash_max_qty` 作为不启用融资买入的做空容量上限，是在该官方语义下结合当前模拟账户空仓实测得出的项目解释，不冒充官方字段的额外业务定义。保留 `margin_max_qty` 审计但不得使用后者放大仓位或启用融资买入。每个候选必须按当时价格逐标的复核，账户不是 `lb_papertrading`、接口失败、数量不足、存在同标的多头/买单或账户快照过期时仍须阻断。
- 合同验收可在正式测试编号生效前配置一个唯一纽约交易日的自然信号验证窗口。只有模拟账户已确认、账户快照可信、实际持仓/挂单/待确认订单全部为零、当前日期和常规交易时段精确匹配时才能自动开启；不得制造订单或降低策略门槛。验证窗口结束后必须先停止新开仓并清理验收持仓，全部归零后才能等待次日正式统计编号。
- 视觉影子实时会话只接受 SDK 常规交易时段形成的真实五分钟K线；盘中重启恢复用的 `context_only` 行不得计入有效会话，也不得作为无效数据污染会话。历史回放必须绑定冻结的逐根数据快照，不能拿滚动日线上下文和旧审计直接比较。视觉影子永远不得生成订单，只有完整会话和人工样例验收全部通过后才能另立纸面合同。
- 虚拟分仓敞口的事实源固定为当前正式测试编号的未平成交批次：`remaining_quantity × open_price`，再叠加未完成券商开仓订单的剩余名义金额。不能用当日订单列表或标的级净持仓猜测跨日分仓归属。
- 精确成交批次显示仓位已经超限时，剩余额度必须为零，只阻断新增和加仓，不阻断止损、止盈或账户退出。精确归因缺失或不一致时继续冻结相关标的新开仓，不回退到可能漏算的日内提交口径。
- 退出执行顺序固定为止损、其他退出、开空、开多。同一成交批次的退出失败后必须冷却 `900s`；仅当账户订单读取成功，且按 `signal_id/client_request_id` 在未完成订单、当日订单和历史订单中均未发现对应活动或已成交订单时，才能生成新的退出重试。响应超时本身不能证明券商没有收单。
- 长桥策略成绩必须从长桥实际 `Filled` 成交重建完整交易批次。一次开仓被多次部分退出时，退出成交事件数可以大于完整交易数；只有来源开仓批次的剩余数量归零后才计为一笔完整交易。策略和资金池必须分别展示完整交易数、退出成交事件数、毛盈亏、估算费用、扣费后盈亏、胜率、盈利因子和最大回撤，禁止把退出成交次数当作交易笔数。
- 当前美股费用模型采用保守估算：每侧订单平台费 `1.99 USD`，每张卖单监管费 `0.02 USD`。费用按实际成交订单和成交数量分摊，字段必须明确标记为估算，不能冒充长桥实际扣费。以后若 SDK 返回可逐笔核对的实际费用，只允许用券商实际费用替换估算，不得把本地模拟费用混入长桥成绩。
- 系统故障日必须从正常策略判断样本中单独剥离。账户快照过期、非模拟账户通道或延迟信号缺少实时重建价格等系统故障导致的完整交易，继续保留在全量审计和账户总口径中，但不得进入正常策略胜率、盈利因子和回撤；看板必须同时显示正常样本、故障日样本和全量样本。
- 三条受限做空仓必须记录完整漏斗：看跌结构候选、路由通过、券商可开数量校验、取得长桥订单号、部分成交和完全成交。券商可开数量成功结果可按标的短时缓存，只有价格变化不超过配置阈值时才能复用；失败结果只能短暂缓存并继续安全阻断。执行流水必须记录数据来自实时查询还是缓存、缓存年龄、券商返回数量和耗时，不能只显示“没有成交”。
- M15 SDK 账户工作进程返回关键字段错误时不得发布为健康快照。必须保留上一份可信快照及其原始时间戳，终止并重建工作进程；连续不可信结果达到阈值后熔断并停止新开仓。可信恢复后才清零连续异常计数。任何恢复逻辑都不得延长旧快照的 `45s` 安全寿命。
- M15 SDK 全部运行配置必须共用用户级全局运行锁，不能因输出目录不同启动第二条行情连接。订阅失败计数必须覆盖超时、子进程退出、覆盖不完整和就绪验证失败等真实路径；达到最大连续失败次数后停止新开仓并等待明确恢复。原 147 只交易池必须由独立快照文件和指纹固定，300 只订阅池的顺序或成员变化不得静默改变交易池。
- 三条受限做空仓的单标的名义金额上限固定为 `750 USD`，每仓总敞口仍为 `2000 USD`、单笔最大风险仍为 `10 USD`。该名义金额下限用于确保既定的风险距离、目标 R 倍数、双边费用和扣费后净利润门槛在数学上可同时满足；不得把单标的上限降到导致理论最高净利润低于策略最低净利润的值。做空结构、质量分、盈亏比和扣费后净利润门槛不得因此降低。路由器必须按短仓正式测试编号累计唯一候选及阻断原因，看板必须显示每条做空运行单元的候选数、可提交数、阻断数和最近候选时间。
- 长桥正式测试的退出管理应以后台完整成交归因作为盘中增量归因的基线，再叠加最新长桥成交；不得因为热快照历史窗口较短而遗失已确认开仓批次。完整对账缺少的止损价、目标价和实时信号信息必须按长桥开仓订单号从实时执行审计补回，不得按标的、价格或数量猜测。清仓前或其他测试编号成交不得进入正式分仓退出管理。
- 已生成但从未进入执行流水的退出事件可以用新的重试编号按当前行情重新确认；已经进入执行器、已经取得长桥订单号或仍处于未终态的退出不得重复提交。重复未归因异常按异常类型、长桥订单号和成交编号去重；真实数量不一致继续冻结对应标的。
- 退出管理的固定单轮数量只限制普通止盈等非紧急退出；已按长桥实际持仓和精确成交批次核验的止损不得因固定名额排队，必须在当轮全部进入 SDK 执行节流队列。无法安全归因但用户明确授权清理的账户持仓必须走一次性账户对账清理状态机：只允许 `lb_papertrading`、只卖长桥实际可卖数量、只在常规交易时段提交市价退出，取得订单号后只跟踪不重发，并从具体策略和分仓成绩中排除。
- 所有账户快照年龄门禁必须区分合法的 `0` 秒与缺失/非法值；不得使用 `value or fallback` 解析允许为零的时效字段。缺失、非数字或负数必须失败，`0~45s` 才可通过当前 M15 开仓验收。
- 长桥正式测试的分仓和策略成绩必须来自精确成交归因。唯一允许的开仓批次身份为“测试编号 + 资金池 + 运行单元 + 方向 + 标的 + 长桥订单号 + 长桥成交编号”；不得按同标的、近似价格、近似数量或本地提交顺序猜测归因。部分成交、分批退出和剩余数量必须逐批记录；未匹配、跨测试编号或净持仓不一致时，冻结受影响标的新开仓并等待长桥事实源修复，禁止自动替其他策略平仓。
- 对已经通过人工卖出、历史跨测试编号净额或旧路径差额处理完毕，但虚拟成交批次仍残留的标的，只允许使用显式账户对账调整清理。调整必须同时满足：长桥实际净持仓为零、列出精确历史开仓订单号、记录长桥成交或人工处理证据、明确不计入资金池和策略成绩。调整不得按标的全量抹除，不得匹配未来同标的新开仓；任一条件不满足时继续冻结并等待核对。
- M15 盘中账户读取必须运行在独立可终止的工作进程，不得让 SDK 资产、持仓或订单读取卡住主交易循环。常规快照刷新硬期限为 `8s`，首次建立 SDK 连接可单独使用 `30s` 启动期限；第一次超时后终止并重建工作进程，在同一轮最多再试一次，连续异常进入 `15s` 熔断恢复。保留上一份可信快照时必须保留原始时间戳，超过 `45s` 仍停止新开仓。只有 SDK 明确返回 `lb_papertrading` 通道才算模拟账户验证通过，不得根据旧状态或默认值放行。
- M15 SDK 实时运行层必须持有单实例文件锁。启动器和后台看护只能把锁持有者写入 PID 文件；重复启动者必须立即退出，禁止多个运行进程同时写行情、账户、归因或状态产物。配置指纹变化时只允许安全替换锁持有者一次。
- 长桥资产页“当日盈亏”按官方公式计算：`最新价*当前数量 - 昨收价*昨收数量 + 当日卖出成交额 - 当日买入成交额`。开启美股盘前盘后时使用对应扩展时段价格，手续费不计入该字段。输入必须全部来自长桥 SDK 的实际持仓、成交和行情。
- `profit_analysis_by_market` 单日结果属于“纽约交易日收益分析”，必须单独展示，不得再作为 App 资产页当日盈亏。App 口径总现金为美元可用现金加冻结现金；App 口径总资产为总现金加当前持仓市值。任一输入缺失时显示不可计算，不回退本地模拟。
- 慢速订单和成交对账首次运行可拉完整测试区间；可信历史缓存存在后只拉最近两天增量，并按长桥订单号和成交编号覆盖合并。禁止每5分钟重复拉取全部历史订单，避免只读统计超时拖成持续看护报警。
- M15 SDK 账户轮询和订单执行必须使用不同的 `TradeContext` 与不同的请求限频锁。账户只读连接发生明确 `request timeout` 时，只允许在冷却期内重建该只读连接并重试一次；不得重建、阻塞或回退订单执行连接，非超时错误不得自动重试。
- M15 在纽约盘后重启时，如果磁盘日线缓存已经通过成员、每标的 60 根和最新完整交易日校验，必须直接复用并标记本交易日盘后刷新已完成；不得在每次进程重启后清空有效缓存重新拉取。
- 长桥 SDK `profit_analysis_by_market` 使用同一纽约交易日作为 `start/end` 返回的 `profit`，固定标记为“纽约交易日收益分析”。完整区间累计盈亏必须单独查询、单独展示；已平仓成交毛盈亏、持仓浮动、收益分析和 App 资产页当日盈亏不得互相替代。
- M15 盘中账户快照只能读取现金、购买力、持仓、当日订单和成交等交易必需字段；`profit_analysis_by_market`、完整历史订单/成交和策略盈亏统计必须留在后台慢路径。收益分析超时不得拖慢 15 秒账户快照或使快照超过 45 秒开仓安全线。交易必需字段发生瞬时 SDK 错误时，只允许在账户通道仍为 `lb_papertrading` 的前提下保留上一份完整健康快照，并保留其原始 `generated_at` 供 45 秒门禁判定；不得用失败刷新把健康账户立即改报为非模拟账户，也不得延长旧快照寿命。账户通道变化时必须立即拒绝保留。
- M15 SDK 账户快照中的总资产必须优先使用 SDK 明确返回的 `current_total_asset`；该字段缺失时使用 `account_balance.net_assets`，并必须同时输出原始币种。`USD available_cash` 只能表示美元可用现金，不能把基础币种为 `HKD` 的账户净资产标成美元，也不能因盈亏分析接口不返回总资产而写成 `0`。
- 长桥看板必须把交易核心时效和慢统计时效分开判断：SDK 进程、订阅和账户快照健康时，旧订单/盈亏统计过期只能显示“交易核心正常、统计待刷新”，同时清空过期统计值；不能把过期数字继续显示为实时值，也不能因此误报交易进程死亡。
- “长桥已配置运行单元”不等于“当前可下单运行单元”。当策略自身固定目标盈亏比低于执行硬门槛时，必须保留 `blocked_reward_r_below_minimum`，并在状态中明确列入目标/止损几何修复；不得为了制造交易而降低硬门槛或静默抬高策略目标价。
- M15 长桥 SDK 是唯一盘中交易主系统。自动交易、账户快照、订单维护和长桥看板禁止调用 CLI、M12/M13/M14 或本地模拟账本。
- 用户界面统一使用“本地研究与修复系统”；内部 M12/M13/M14 只代表本地行情与信号、本地模拟账本、策略修复评估三个审计步骤。该系统仅在纽约收盘 15 分钟后运行一次，失败最多重试 3 次且不得阻断 M15。
- 本地研究与修复系统由开机后台进程运行时，Longbridge 只读程序路径不得只依赖守护进程的 `PATH`。报价和历史 K 线读取必须依次解析 `LONGBRIDGE_CLI_PATH`、系统 `PATH` 和 `~/.local/bin/longbridge`；该兼容只用于盘后只读数据，禁止进入 M15 SDK 自动交易热路径。
- 本地盘后日线缓存存在但未覆盖最新交易日时，只允许从缓存末日之后增量补齐并与原缓存按时间戳合并，禁止每天重拉全部历史。147 只股票的日线和当日五分钟数据属于两个独立目标，单轮抓取预算必须至少覆盖 `147×2`；任一周期不满 `147/147` 时不得把严格全量扫描标为完成。
- 开机脚本只启动 M15 SDK、M15 后台看护和本地盘后调度器。M12.47/M12.37、旧 CLI 守护器、快速队列和全策略订单预览不得自动启动；readiness 中 M12.47 只能是非阻断兼容信息。
- Windows 隐藏登录启动器必须直接使用 `wsl.exe -d Ubuntu --exec bash <bootstrap> --keep-alive`，不得通过多层 `bash -lc` 引号拼接。PowerShell `Register-ScheduledTask` 因权限被拒时，安装器应先保留登录启动器，再尝试用当前用户可用的 `schtasks.exe` 建立工作日北京时间 20:45 的隐藏唤醒任务；两种计划任务方式都失败时才退化为仅登录启动。20:45 比美股夏令时开盘提前 45 分钟，可覆盖冷启动重新装载 8820 条日线及有界重试。长期连接在 WSL 内每 60 秒幂等检查一次 M15 SDK、后台看护和本地盘后调度器；不得通过 Windows 周期性重启 `wsl.exe`，也不得弹出终端窗口。
- M15 后台看护必须持有单实例运行锁；并发启动只能保留一个进程。健康状态变化立即记录，稳定健康摘要最多每 5 分钟写一次。SDK 慢统计只能在 `lb_papertrading` 账户快照不超过 `45s` 时运行，不能用过期账户状态生成新时间戳统计。
- M15 后台看护不得只依据子命令进程退出码判定健康。SDK runtime 返回非 `running`、`sdk_connected!=true` 或账户快照不健康，opening readiness 返回 `blocked_*`，以及 SDK-only acceptance 返回 `blocked_*` 时，都必须把本轮看护标为 `needs_attention`；运行层状态仍在推进且进程存活时只报警和等待其有界自愈，不得因此反复重启主进程。
- M15 SDK 订单维护只能处理能从长桥订单备注明确归因到实时执行流水的订单。长桥备注格式允许包含固定前缀、`signal_id` 和 `client_request_id`；维护器必须解析其中已知 `signal_id`，不得要求整段备注等于信号编号，也不得撤销人工或无法归因的订单。未成交开仓单超过配置有效期后必须撤销并释放虚拟仓占用。
- SDK 慢统计还必须核验实际 SDK 运行进程存活、状态更新时间和配置指纹；任一不一致都必须停止本轮统计刷新。慢统计的 `300s` 上次成功时间必须跨连续跳过轮次保留，禁止因状态文件被跳过结果覆盖而提前重复调用历史订单和盈亏接口。
- 持仓退出管理必须分别按做多正式测试编号和做空正式测试编号读取执行流水：做多持仓只用做多编号归因，空仓及回补只用做空编号归因；两组当前流水可以合并用于防重和冷却，但不得先按做多编号过滤后再寻找空仓。
- 周一/开盘验收的唯一事实源是 canonical SDK readiness 与 SDK-only monday acceptance。旧 CLI readiness 路径只能写“已停用并指向 canonical 路径”的标记；M12/M13/M14 盘后产物不得重新成为 M15 开盘门禁。
- SDK-only acceptance 不得把后台看护上一轮汇总状态作为自身通过条件，因为后台看护会调用 acceptance，双向依赖会把一次瞬时重连固化为永久失败。acceptance 只检查 SDK 进程、行情、账户、正式测试编号、开盘验收、看板事实源和安全边界；后台看护单独检查 acceptance 并负责报警。
- 正式基线处于 `pending_flatten` 时禁止所有新开仓。常驻 SDK 仅在美股常规交易时段按长桥实际持仓执行清仓：多头市价卖出、空头市价回补；明确拒绝且没有订单号时只允许一次两秒内行情的可成交限价退路。持仓、挂单、待确认订单任一非零或未知时不得激活正式测试编号。
- 普通策略开仓继续只允许限价单或触发限价单；市价单仅允许正式清仓、止损退出和明确退出。所有请求必须使用稳定请求标识防重，未取得订单号的请求只能待确认，禁止补发。
- 长桥独立看板只读取 SDK、长桥模拟账户、实际订单/成交、分仓归因、正式测试编号和长桥盈亏对账。长桥成绩只统计实际成交，不得从本地账本、旧提交器或旧队列回退取数。
- 平仓归因必须核对来源开仓信号或订单的 `test_epoch_id`。跨测试编号的真实成交保留在长桥账户总口径，但必须从具体资金池和策略成绩排除，禁止把旧持仓退出算给新正式测试策略。
- 本地研究股票池固定使用独立 147 顺序快照。M15 扩展到 300 只时必须继续使用唯一一条 SDK 行情长连接：原 147 只是交易股票池，新增 153 只只能进入只读行情与日线上下文，不得进入策略路由、风控或订单。全局行情锁必须独立于输出目录，禁止通过另一份配置并行启动第二条长连接。新增 153 只至少完成一个常规交易日的 `300/300` 订阅、`18000/18000` 日线、账户快照和延迟验收后，才能另行批准进入交易股票池。
- 行情事件和大型本地修复流水按日/测试编号压缩，但当前活跃文件不得压缩；订单、成交、分仓归因永久保留。压缩先 dry-run，盘后批处理成功后才执行。
- 已退出自动路径的 CLI 会话、旧账户快照流水和旧权益流水可按交易日压缩；M14 自动生成的 JSONL 流水不再由 Git 跟踪。长桥订单、成交、正式分仓归因和订单对账继续永久保留，不能因瘦身删除。

## 1.1 当前 M14/M15 策略推进规则

- M15 长桥实时会话守护器文本日志只用于人工排查，不参与风控、去重、持仓归因或状态恢复；启动前若日志超过保留上限必须归档旧日志，非交易窗口等待状态不得每轮重复刷同一句日志，避免长期常驻后巡检和看板排查被大日志拖慢。
- 模拟订单启用必须使用 SDK 正式配置并运行 `scripts/run_m15_opening_trade_readiness.py`。只有 M15 SDK 实际进程存活、运行引擎为 `sdk`、实际配置指纹与预期一致、账户确认为 `lb_papertrading`、`execute_orders=true`、`paper_trading_approval=true`、原 147 只交易池订阅和日线完整、账户快照不超过 `45s`、实盘/真实资金/真正碎股/期权/融资全部禁用、修复策略和辅助模块隔离，并且做空仅限本文件定义的三条受限短仓时，才允许在常规交易时段提交长桥模拟账户订单。M12.47 仅属于已退出盘中主链路的历史兼容信息，不得阻断 M15。
- Windows 后台自启只允许调用 `scripts/start_m15_trading_stack_after_boot.sh` 这类守护器启动脚本，启动范围限定为 M15 长桥 SDK 实时运行层、M15 后台看护器和本地盘后调度器；不得在开机脚本里手动运行 M12.37 once-mode，不得加入 `--no-fetch` 或 `--no-refresh-quotes`。Windows 计划任务必须是用户级隐藏任务，并同时具备“用户登录时”和“工作日北京时间 20:45”两个单次触发器：前者覆盖开机登录，后者覆盖 WSL 发行版被系统单独回收后没有重登 Windows 的情况。若 PowerShell 注册接口被拒，允许使用 `schtasks.exe` 创建同等的用户级隐藏唤醒；两者都失败时才退化到隐藏的一次性登录启动项，不得回退到 `300` 秒循环。
- 长桥实时执行器在提交触发限价单前必须做最后一层订单类型校正：如果买入触发价已经等于或低于当前价，说明突破条件已到达，必须降级为普通限价单并记录审计原因；不得把这种信号继续作为 `LIT` 触发单提交给长桥，避免被接口拒绝。
- `m15_longbridge_fast_signal_queue` 从长桥提交来源降级为本地审计/历史兼容产物；`scripts/run_m15_all_strategy_order_preview.py` 也只保留为本地复盘和稳定性审计，不得作为长桥实时下单热路径。旧快速队列仍可用于研究重复信号、共振和费用门槛，但不能再给长桥提交器提供待提交订单。
- 长桥实时白名单只包含非修复、非辅助、非影子救援的正式运行单元。修复策略、救援变体、影子参数策略只跑本地模拟，不创建长桥实时信号、不进入长桥实时风控、不占长桥实时资源；辅助模块只服务本地策略评分、止损、仓位、目标价和图形证据，不独立下单。
- 周一前只能准备 M15 预演、白名单、仓位、熔断和验收清单；周一交易时段必须等 M12.47 自动拉起 M12.37 fresh refresh，行情来源为 `longbridge_quote_readonly` 后才能重算 M13/M14 和继续长桥模拟账户预演。
- M12.37 盘中自动刷新配置必须允许 `postmarket_or_runtime_ready`：只要 M12 当天行情和账户化运行数据已准备好，就可以在美股常规交易时段重算 M14，避免 M15 模拟账户提交器因为“当天策略复核只等盘后”而无法提交当日新信号。仍禁止手动运行 M12.37 once-mode。

## 2. 每个 milestone 的流程

1. 确认当前 milestone。
2. 按 `docs/branching.md` 创建分支。
3. 判断是否需要 subagent。
4. 派发 researcher / data_engineer / kb_curator / implementer / reviewer / qa。
5. 等待 subagent 结果。
6. 读取 handoff。
7. 主 agent 集成。
8. reviewer 审查。
9. qa 验证。
10. 更新 `docs/status.md`、必要时更新 `docs/decisions.md` 和 `plans/active-plan.md`。
11. 未触发阻塞时继续下一个 milestone。

## 3. 何时必须创建 subagent

满足任一条件即必须显式创建：

- 2 个以上独立子任务。
- 同时涉及探索、实现、审查、测试。
- 同时涉及知识库和代码。
- 涉及多个模块边界。
- 涉及高风险模块。

## 4. 防死循环

- 同一子任务失败 3 次，熔断。
- reviewer 连续打回 3 次，熔断。
- 熔断后输出 Failure Dossier。
- 禁止盲目继续尝试。

## 2026-08-06 M15 退出归因与非交易时段行情规则

- 长桥账户级清仓成交必须写入执行审计，并保留实际 `order_id/trade_id`。虚拟仓回填只能在长桥当前持仓已归零、清仓订单为实际 `Filled`，且同标的待清虚拟数量与实际成交数量精确一致时进行；按开仓批次 FIFO 分配，但不得跨测试编号、资金池、运行单元、方向或合同哈希猜测策略归属。
- 同一策略一次汇总退出多个开仓批次时，只有本地退出意图声明的总数量与长桥实际成交数量完全相等，且 `test_epoch_id + capital_bucket + runtime_id + direction + strategy_contract_hash + symbol` 全部一致，才能把该成交分配到对应批次。任一字段或数量不一致必须保留为未归因异常。
- 历史归因修复默认只读；`--execute` 只能追加审计调整，不允许重写或删除长桥订单、成交及原执行流水。重复运行必须幂等。
- 已验证稳定的 `sdk_snapshot_poll` 模式可在非交易时段复用：先完成一次 `300/300` SDK 快照探针，随后仅维持行情工作进程心跳，避免重复启动已知会超时的订阅探测。交易时段仍由唯一 SDK 行情连接提供实时事件；任何后备模式都不得制造行情事件或补交旧信号。

## 5. 何时问用户

只在以下情况问用户：

- 需要真实账户、凭证、付费服务或外部权限。
- 需要决定是否进入下一阶段。
- 需要决定高影响架构取舍。
- 需要业务验收或实盘审批。
- 熔断后需要用户选择继续方向。

其他情况下，主 agent 自主推进。

## 6. 完成前检查

任务完成前必须确认：

- 在正确分支上完成。
- 测试或验证已运行。
- 文档已同步。
- status 已更新。
- handoff 已归档或摘要写入 status。
- reviewer 通过。
- qa 通过。
- M15 SDK 慢速统计必须从正式测试标记读取 `test_epoch_id`、`short_test_epoch_id` 与 `test_started_at`；同编号但早于开始时间的完整交易只能进入历史审计。显式系统故障日只排除策略成绩，不得改写长桥账户真实盈亏。跨策略同标的退出必须引用真实未平开仓订单和成交号；已发生且证据完整的错配只能通过批准的账户对账调整结清，并禁止计入任何策略成绩。
- 长桥净资产展示必须把数值、币种和来源视为不可拆分的一组。App 公式完整时三者均使用同一公式结果；公式不完整时三者均回退到 SDK 账户净资产，禁止出现 HKD 数值配 USD 标签。无法获取 App 顶部当日盈亏时显示不可确认，不得用交易盈亏、持仓浮盈或本地估算冒充。
