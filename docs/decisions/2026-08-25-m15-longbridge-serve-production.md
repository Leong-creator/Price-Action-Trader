# M15 生产行情改用 longbridge serve

## 决定

M15 的唯一盘中行情传输固定为一个长期 `longbridge serve 0.28.2` JSON-RPC 会话。账户资产、持仓、订单提交、撤单和订单状态仍全部使用官方 Longbridge SDK；行情进程不得调用任何 `trade.*` 方法。

生产配置固定：

- 区域：`cn`，不修改系统代理。
- 策略池：147只。
- 池外已有持仓：追加到同一行情会话，只用于估值和退出。
- 订阅字段：`quote + trades`。
- 订阅批量：每批10只。
- 快照用途：订阅初始状态和缺失初始报价补齐，不拥有开仓资格。
- 自动快照轮询回退：关闭。

## 原因

官方SDK在当前机器和账户上对3只标的可持续推送，但147只单连接只在启动后短暂推送，随后静默并反复重建。相同账户、网络和标的使用长期 `longbridge serve` 时能够持续收到报价和逐笔成交，因此行情传输改用后者。此前已经稳定工作的SDK账户和订单路径没有替换，避免扩大改动范围。

- 逐笔成交事件：22543条，120只在该时段有成交推送。

正式行情子进程另完成60秒父子接口验证：147只策略池和9只池外持仓监控标的共156只全部订阅并取得初始报价；收到544条行情状态和56次心跳，队列积压0，读取错误0，SPY/QQQ均有实时活动，进程正常退出。

## 安全边界

- `longbridge serve` 客户端在本地使用方法白名单，只允许 `initialize`、`quote.subscribe`、`quote.unsubscribe`、`quote.quote` 和 `shutdown`。
- 行情可执行文件必须与生产配置中的SHA-256一致。
- 每次重连只清理由M15专属环境标记识别的遗留进程，不影响人工或其他应用。
- 新开仓仍由完整交易日行情门禁控制；上述一小时证据不能替代78个五分钟边界验收。
- 完整交易日通过前只允许已有持仓在实时行情证据有效时退出，不允许快照或历史数据触发订单。

## 回退

若完整交易日验收失败，停止新开仓并保留账户事实读取；不得自动回退到SDK行情或快照轮询。代码回退使用本决策对应的版本标签和反向提交，不在交易时段修改生产源码。
