# M15 行情传输对照决定

> 2026-08-25 更新：本文件关于“每批10只”的候选结论已被 `2026-08-25-m15-single-subscription-request.md` 取代。

- 正式行情选型前，使用未修改的官方 `longbridge==4.5.0` 和支持 `longbridge serve` 的官方 CLI 做串行只读对照。
- SDK 对照固定四组：3只报价、147只报价、147只逐笔成交、147只报价加逐笔成交；每组默认30分钟，可延长到60分钟。
- 对照程序不加载策略、账户或订单派发，不修改代理，不并行建立多个行情连接。
- 只有订阅回执、服务端订阅列表、逐标的首末推送、事件数和资源变化全部可核验，结果才可用于正式传输选型。
- CLI `serve` 仅作传输候选；账户和订单继续使用 SDK。旧版一次性 CLI 命令不得进入行情热路径。

## 2026-08-22 非交易时段冒烟证据

- 未修改官方 SDK `longbridge==4.5.0`：3只报价订阅为 `3/3`；147只按每批10只时，报价、逐笔成交、报价加逐笔成交三组订阅均为 `147/147`。
- 147只按每批50只时首批请求出现 SDK 原生 `request timeout`。正式候选固定每批10只，完整30至60分钟及交易时段证据仍待执行。
- 周末没有真实逐笔成交，当前只能证明订阅建立和报价首推，不能宣称完整交易时段稳定。
- 官方 `longbridge serve 0.28.2` 已在项目隔离目录通过校验值安装；当前 CLI OAuth 缓存刷新返回 `invalid_request`，CLI 对照状态是“认证阻断”，不是传输失败。不得因此回退旧版轮询 CLI。
