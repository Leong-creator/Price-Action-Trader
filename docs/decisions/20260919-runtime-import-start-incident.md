# 2026-09-19 运行模块导入误启动事件

## 事实与范围

独立审查尝试只读导入运行模块时，模块顶层的解释器重执行逻辑缺少 `__name__ == "__main__"` 限定，导入意外转为启动CLI。发现后立即中断并回收进程。**这是实际发生的运行入口缺陷，不是授权的行情诊断，也不是验收证据。**

私有证据保存于 `20260919-official-baseline/unintended-import-start/incident.json` 及其列明的5个运行文件；这些文件不包含在公开文档中。

- 行情worker被启动，读取日线进度达到49/147时中断，订阅0/147。
- 账户worker也被启动，并完成 `lb_papertrading` 模拟账户的只读快照验证。因此不得将整个本轮过程概括为“未访问账户”；无账户操作的结论仅适用于登记的官方独立示例。
- 运行记录 `dispatch_requested=false`、`dispatch_enabled=false`，提交日志0字节；本地证据没有订单派发请求。该事件没有执行额外券商订单查询来扩张结论范围。
- 主工作区受保护的5个故障/启动审计/提交日志/编号状态文件哈希均与冻结记录一致；事件文件来自任务工作区，不以其覆盖正式故障状态。
- 相关进程已停止，未发现遗留活跃行情/账户spawn；退出核查由主代理留证。

## 修复与验收状态

候选修复已给解释器重执行添加 `__main__` 入口限定，并补充真实子进程import哨兵测试，要求导入不启动CLI、不创建worker或访问网络。修复由运行层代理实施，离线组合回归已完成（795通过、2跳过，相关147项重跑通过）；真实import哨兵测试属于监督模块，独立复核仍由主代理汇总。未正式部署，也不以修复入口误启动缺陷解释行情订阅超时。

本事件与官方独立异步示例的订阅超时分别处理。后者没有导入项目运行模块，不能用此入口缺陷解释官方示例超时，也不能用误启动的日线/账户结果证明行情修复成功。
