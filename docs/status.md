# 项目状态

## 当前结论

- 代码基线：`main` 已包含工作区治理、行情对照、官方 SDK 单长连接、五分钟K线完整性、恢复状态机和行情可观测性。
- 账户边界：只允许 `lb_papertrading`；实盘、真实资金、期权和融资未启用。
- 行情传输：生产只允许 `official_sdk_persistent_websocket`。固定147只策略池与池外已有持仓监控标的使用一次 `Quote + Trade` 订阅请求，当前合计156只，低于官方500只上限。
- K线：逐笔成交生成五分钟开高低收和成交量；无成交标的生成 `no_trade_carry_forward` 零成交平K线且禁止开仓。
- 订单资格：初始快照、诊断快照、历史K线和盘后补录均不能触发新开仓。
- 当前门禁：新的完整交易日行情门禁尚未取得证据，因此模拟账户新开仓保持关闭。

- 2026-08-22 实机复核：官方 SDK 单长连接存活，147/147订阅、8820/8820日线、模拟账户端点和账户快照均健康；行情工作进程代次为1，未发生快照轮询、重连或熔断。
- 2026-08-22 验收状态：开盘验收和综合验收均为0失败，后台看护健康；新开仓只因尚缺一个完整交易日实时行情证据而关闭。
- 2026-08-24 重启巡检发现 Windows 隐藏启动入口仍引用旧的 `contract_v1` 运行配置，导致部署清单按预期拒绝旧进程。启动入口、运行库默认值和兼容配置现已统一到正式生产门禁，并增加防回归测试；策略合同和风险参数未改动。
- 2026-08-24 账户与行情覆盖复核发现24个实际多头持仓中有9个不属于固定147只策略池。运行层现从账户快照提取这些持仓并在同一SDK行情连接追加“只监控、只退出”订阅；运行中出现新的池外多头时自动重建唯一行情连接。策略路由仍严格限定147只，额外持仓不能新开仓，也不计入147只K线完整性门禁；来源不明的池外空头不自动接管。额外订阅失败只停止新开仓并单独报警，不熔断147只主行情验收，其他可监控持仓仍可退出。
- 2026-08-24 长桥看板策略清单已改为读取正式 `paper_contract_v1` 执行配置，不再把19条退休简化版和实验仓历史配置显示为当前运行策略；当前正式合同白名单为5条做多和3条做空，共8条。
- 2026-08-24 盘中重启发现周期性账户快照与行情订阅同时冷启动时，官方SDK行情子进程会在部分批次超过30秒无进度并进入恢复循环；同账户、同156只标的的隔离只读订阅实测全部成功且单批约0.05秒。运行层现先读取一次可信账户快照，暂停周期性账户请求，行情订阅完成后再恢复15秒账户刷新；行情重连采用相同顺序，优雅退出窗口覆盖账户和行情子进程清理时间。策略、仓位和订单条件未改动。
- 本轮继续实机复核确认，连续杀死并重建行情子进程会重复发起156只全量订阅并形成请求风暴，反而延长官方SDK部分批次的等待时间。冷启动单批无进展窗口现独立放宽到90秒；连续三次失败后主进程保持存活、账户刷新继续、停止新开仓，冷却300秒后由同一进程重试。看护器不再通过替换父进程制造每分钟全量重订阅。
- 部署复核进一步确认，若行情订阅期间暂停账户刷新，首轮90秒超时会使账户快照超过看护器替换门槛，仍会重启父进程。账户快照现从行情订阅生命周期彻底解耦并始终按15秒刷新；行情可独立冷却重试，账户和已有持仓退出状态保持可信。
- 独立只读诊断进一步定位到多请求序列本身：147只按每批20只时前140只成功，第8次请求在30秒超时；缺失的7只单独订阅用时529毫秒且全部成功，一次订阅147只用时866毫秒、一次订阅147只加9只池外持仓共156只用时530毫秒，均完整成功。生产因此改为单次156只请求，避免多请求序列触发SDK等待；逐标的诊断只保留在隔离工具中，不进入生产连接。
- 单次156只订阅部署后确认服务器订阅和初始快照均完整，但父进程只用报价回调判断活跃度，忽略仍在流入的逐笔成交，造成30秒静默误判和行情子进程重建。参考标的 SPY/QQQ 的逐笔成交现以每秒最多一次的轻量活动心跳上报；健康判断接受报价或成交推送，K线和策略输入不变。
- 2026-08-25 交易时段持续推送复核更正了上一条的结论：官方SDK三只标的报价和逐笔成交可连续推送30秒，但147只单请求虽返回完整订阅回执，报价和逐笔成交都只在启动后短暂到达；生产进程6分钟内重建到第9代且可交易五分钟K线仍为0。因此该问题不是父进程遗漏逐笔成交心跳，147只正式行情仍未通过。新开仓继续关闭，策略和仓位未修改。
- 静默恢复计数现不再在“订阅回执成功”时清零；只有行情连接持续超过30秒且SPY/QQQ至少一个仍有新鲜推送时才确认恢复。连续三次只短暂启动便停流的连接会进入300秒行情熔断，停止新开仓但保留账户快照和已有持仓退出，不再无限重建行情子进程。

- 看板统计重启后暂不可计算时只影响展示，不再阻断已由实时账户快照保护的交易链路；看板数据源仍必须是长桥 SDK 模拟账户。
