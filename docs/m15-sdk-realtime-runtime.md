# M15 长桥实时运行层

## 目的

M15 的长桥模拟账户实时链路由长期行情推送驱动：`longbridge serve` 报价/逐笔成交推送 -> 五分钟 K 线完成 -> 实时信号 -> 快速风控 -> 长桥 SDK 模拟订单请求。它不读取本地模拟账本，也不使用旧快速队列作为下单来源。

实时运行层的入口是 `scripts/run_m15_longbridge_sdk_runtime.py`，配置为 `config/examples/m15_longbridge_sdk_runtime.json`。行情传输固定为 `longbridge_serve_persistent_jsonrpc`，账户和订单传输固定为持久 SDK 上下文。最终 K 线继续写入 `m15_realtime_market_events.jsonl` 契约，因此路由、执行、看板与审计字段协议保持不变。

## 运行边界

- 仅允许 `lb_papertrading` 模拟账户；实盘、真实资金、期权和融资保持关闭。
- 行情使用一个长期 `longbridge serve` 子进程订阅；下单复用持久 SDK 交易客户端，行情CLI不得调用提交、撤销或修改订单接口。
- 历史订单、成交对账、盈亏统计与日报继续在慢路径执行，不能阻塞实时订单处理。
- 实时事件文件在热路径只追加写入；每分钟心跳压缩为最近 20,000 条。SDK 运行进程保留必要的日线和盘中 K 线上下文；重启时只从自身事件文件恢复当天、每标的最近 20 根 SDK 五分钟已完成 K 线，作为结构判断历史。路由器仍只把本轮新事件作为信号触发源，执行器直接接收本轮新信号，因此不会重放旧信号或旧订单。
- SDK 订单显式指定常规交易时段、日内有效和纸面账户边界；影子配置默认禁止订单派发，防止 OAuth 完成后意外启用模拟下单。
- `1` 秒是信号产生到发起模拟订单请求的优化目标，`5` 秒内仍可接受；超过后必须用当前行情重新确认，不能补交旧信号。
- 延迟主口径在真正发起 SDK 请求时计算，包含同一轮前序订单的串行排队时间；整批策略处理耗时和单笔 SDK 请求响应耗时另行展示。配置、关联配置和实时 Python 源码共同进入运行指纹，后台看护发现任一漂移都会替换旧进程，避免文件已经修复而常驻进程仍运行旧逻辑。
- 运行层停止或配置切换时，只向主进程发出优雅停止请求；主进程先停止行情工作进程，行情工作进程再向 `longbridge serve` 发送 `shutdown`。强制终止后下一次重连只清理带M15专属标记的遗留行情进程，避免重复连接。单笔 SDK 下单异常只写入该笔执行流水，不能让整个行情和下单运行层退出；下一根新 K 线只会为已明确失败、且没有长桥订单号的退出请求生成带新编号的重试意图，不会重复发送已提交或待确认的卖单。
- 行情子进程在五分钟区间中途启动或重连时，必须丢弃启动所在的残缺区间，并在状态里显示 `partial_bar_suppressed_until`；只有下一根从区间起点完整聚合的五分钟 K 线才能进入策略路由。
- 止损和止盈继续使用限价单，但多头卖出限价按当前价下浮 `0.5%`、空头回补限价按当前价上浮 `0.5%` 形成可成交保护区间。限价只是最差可接受价，正常情况下仍按当时更优价格成交；已有同标的退出挂单时不会重复提交。
- SDK 原生挂单维护每 `15s` 检查一次：未成交买入超过 `900s` 会撤销；已归因退出单超过 `60s` 未成交时，按当前长期行情状态重新提供可成交保护限价。维护只处理带精确信号备注的 M15 订单，人工、未归因和部分成交订单不自动改动；状态文件长期保留最近一次实际撤单/改单动作，后续“无需操作”检查不能覆盖该审计证据。
- 本机当前 `longbridge serve` 行情会话固定使用 `cn` 区域；`global` 行情端点在当前网络下会超时。该区域选择不修改系统代理。SDK 的账户查询和订单请求仍走持久客户端，订单终态继续由慢路径只读对账确认。

## 验收后清仓

`scripts/run_m15_sdk_validation_flatten.py` 只用于用户明确批准的单次 SDK 纸面验收收尾。它必须指定授权的纽约交易日并带 `--execute`，且只会在美股常规交易时段、账户明确为 `lb_papertrading` 时工作。脚本先停止 M15 新开仓和后台看护、取消未完成订单，再根据长桥实际持仓方向提交多头卖出或空头回补；撤单最多等待 `30` 秒确认，清仓订单最多等待 `75` 秒确认实际持仓和挂单均归零。方向、价格、可用数量、账户状态或成交确认任一项无法确认时，整批清仓停止，不会猜测、补单或把“已提交”冒充“已清仓”。它不使用 CLI 下单，不读取本地模拟账本，也不会重启交易运行层。只有确认清仓完成后，才写入下一交易日的正式测试基线标记与新 epoch 状态。

如果停机后的账户或报价连接短暂失败，脚本最多做三次只读重试；账户/持仓/订单仍无法确认时整批停止。只有报价读取失败时允许使用长桥持仓成本价生成更保守的保护限价，并记录 `quote_fallback_used`。任何停机后的失败都会把正式测试写为 `pending_flatten`：后续 M15 可以恢复常驻，但执行层只生成长桥实际持仓退出，不处理普通策略开仓；看板和值守必须显示“仅允许平仓”。待长桥确认持仓和挂单均归零后，epoch 才从 `pending_flatten` 变为 `active`。

## 启用前置条件

1. 已在项目虚拟环境安装 `requirements-runtime.txt` 中锁定的 SDK 版本；启动器会自动重启到项目 `.venv`，避免系统 Python 找不到 SDK。
2. 将 OAuth SDK `client_id` 写入 `~/.config/price-action-trader/longbridge_sdk_client_id`，并在浏览器完成该客户端的授权。
3. 使用 `scripts/install_m15_quote_canary_tools.sh` 安装配置锁定版本的 `longbridge serve`，并完成同一用户环境下的 CLI OAuth；生产启动会校验可执行文件和 SHA-256。
4. 先运行 `python scripts/run_m15_longbridge_sdk_runtime.py --check`。它必须显示 SDK 账户/订单前置条件、行情二进制校验和 OAuth 可用。
5. 切换时必须停止旧行情采集器，禁止两个来源同时写入同一事件文件；完整交易日门禁通过前不恢复新开仓。

Windows 隐藏登录启动项只调用 `scripts/start_m15_trading_stack_after_boot.sh` 一次；该脚本直接使用项目 `.venv/bin/python`，幂等拉起 M12.47、M15 SDK 和后台看护。虚拟环境缺失时明确失败，不回退系统 Python，也不创建周期性弹窗轮询。

日线实时确认只对本轮实际收到完整五分钟 K 线的标的生效。当天早先的实时五分钟数据仍用于累计日内开高低收，但报价静默或当前区间没有推送的标的不会拿旧价生成新的日线确认；系统跳过该标的并在运行状态中列出当前批次缺失代码，不伪造可交易 K 线。

`longbridge serve` 的订阅结果快照只用于建立报价状态；实时 `quote.updated` 与快照按行情时间戳合并，较旧数据不得覆盖较新数据。五分钟成交量只累计 `quote.trades` 的逐笔数量，不把快照总成交量或 `current_volume` 重复计入。

当前仓库已完成事件契约、SDK账户/订单客户端、订单号解析、长期行情JSON-RPC适配、增量事件传递和离线测试。SDK与CLI OAuth均使用同一长桥模拟账户边界；行情CLI只允许 `quote.*`、初始化和关闭，自动交易仍全部通过SDK。固定147只策略池与池外已有持仓监控标的共享唯一行情会话，完整五分钟K线按实际边界时间校验新鲜度；运行状态分别记录行情子进程、账户SDK、订阅覆盖、初始报价覆盖、队列深度、读取错误、内存、线程、文件句柄和热路径延迟。完整交易日门禁通过前，新开仓保持关闭，已有持仓退出仍需要实时行情证据。
